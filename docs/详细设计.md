# 失物招领系统详细设计

版本：1.1.2；更新日期：2026-11-21；关联：需求分析 FR-01～FR-07。初版于 2026-11-13 先于代码建立，本次补充个人信息、密码修改、会话撤销和旧库迁移，保留此前登录反馈、检索过滤与暖色页面设计；实际验证另见测试报告。

## 1. 总体架构

浏览器（HTML/CSS/JavaScript） → Spring MVC REST 控制器 → Spring 事务业务服务 → MyBatis Mapper → SQLite。

检索服务通过本机 HTTP 调用 Python 模型服务；模型服务只处理公开文本，不连接账号和申领表。Java 负责权限、筛选、排序融合、事务和结果解释。模型不直接操作业务状态。

Java 使用 JDK 21，Spring Framework 6.2、MyBatis 3.5、MyBatis-Spring 3.0、Jakarta Servlet、嵌入式 Tomcat 10.1。使用显式 Spring 配置与 DispatcherServlet，不使用 Spring Boot。Maven 构建，静态页面由 Spring MVC 提供。依赖版本在 pom.xml 固定。

## 3. 数据模型

所有主键为整数，时间为 UTC ISO-8601 文本，事件日期为 yyyy-MM-dd；前端以用户本地时间显示创建时间。状态字段使用 CHECK 约束。

| 表 | 主要字段 | 关系/约束 |
|---|---|---|
| users | id, username, display_name, phone, default_address, session_version, password_hash, role, status, ban_reason, created_at | username 唯一；角色 USER/ADMIN；状态 ACTIVE/BANNED/DELETED |
| items | id, owner_id, type, title, category, description, location, event_date, contact, hidden_features, status, review_note, created_at, updated_at, deleted | owner_id 外键；type LOST/FOUND；逻辑删除 |
| attachments | id, owner_id, stored_name, mime, kind, created_at | 随机文件名；kind PUBLIC/PROOF；私有附件只能由所有者/管理员读取 |
| item_images | item_id, attachment_id | 联合主键；一张上传只绑定自己的记录 |
| claims | id, item_id, applicant_id, proof, proof_attachment_id, status, review_note, created_at, updated_at | item_id/applicant_id 外键 |
| notifications | id, user_id, message, is_read, created_at | 接收人外键 |
| audit_logs | id, actor_id, action, target_type, target_id, reason, created_at | 不保存敏感证明、密码 |

claims 对同一物品/用户的 PENDING、APPROVED 状态建立部分唯一索引；对每件物品的 APPROVED、COMPLETED 状态建立部分唯一索引，保证进行中和最终领取人唯一。items(status,type,deleted)、claims(item_id,status)、notifications(user_id,is_read) 建立索引。账号注销保留外键身份但清空密码和名称等个人信息，软删除其已结束发布。

## 4. 业务状态与事务

### 4.1 发布

create → PENDING；admin approve → OPEN；admin reject → REJECTED；owner edit → PENDING。修改时检查所有权、状态及是否有历史申请。删除检查状态和申请历史；管理员可关闭并取消进行中申请。寻物 OPEN → RESOLVED；招领 OPEN → HANDOVER → CLAIMED。

### 4.2 申领

create：验证有效账号、FOUND/OPEN、非本人发布、证明与附件权限，再插入 PENDING。重复进行中申请由唯一索引拦截。

approve：在同一事务内检查管理员不是申请人、申请人为 ACTIVE、申请为 PENDING；以 `UPDATE items SET status='HANDOVER' WHERE id=? AND status='OPEN' AND deleted=0` 抢占交接权，影响行数不为 1 则返回 409；随后申请改为 APPROVED，产生通知与审计。

reject：只允许 PENDING，必须提供原因。withdraw：仅申请人将 PENDING 改为 WITHDRAWN。cancel：管理员将 APPROVED 改为 CANCELLED，同时物品 HANDOVER 改回 OPEN。

complete：只允许 APPROVED、物品 HANDOVER、申请人 ACTIVE；事务中物品变 CLAIMED、申请变 COMPLETED、其他 PENDING 变 CANCELLED，分别通知。重复确认返回冲突，不重复发通知。

close：管理员关闭物品并取消所有 PENDING/APPROVED 申请。普通用户只有在无进行中申请且不处于交接中时可关闭自己的记录。有进行中业务时禁止注销账号。

SQLite 写事务通过条件更新和约束保证一致性；忙超时返回可重试冲突，不能通过内存锁代替数据库一致性。

## 5. 接口设计

返回 JSON。成功返回资源或 `{ok:true}`；失败返回 `{error:"中文可操作提示"}`。400 输入错误，401 未登录，403 无权限/封禁/CSRF，404 不存在，409 状态冲突，413 文件过大，429 频率受限，503 服务不可用。列表包含 items、total、page、pageSize；搜索额外包含 mode、suggestions。

| GET | /api/items | q、category、location、type、status、from、to、page、pageSize 查询 |

所有修改接口包含 X-CSRF-Token；使用服务端会话，登录后变更 session ID 和 token。账号身份每次请求重新读取，确保封禁立即生效。账号、物品所有权和审核权限由服务校验。

本轮列表搜索额外返回 minScore：有查询时为 30.0，空查询为 null。修改请求没有有效会话时返回 401 和“登录态过期，请重新登录后再操作”，优先于 CSRF 检查；存在有效会话但 token 不匹配时仍返回 403 和“页面验证已失效，请刷新后重试”。受保护读取请求没有身份时返回 401“请先登录”。前端进入受保护页面、发布或申领前请求 `/api/session`，比较原登录状态；业务接口 401 时清除旧身份、刷新 token、打开含准确说明的登录框。登录接口自身 401 表示凭据错误，不误标为过期。表单保持在内存中，重新登录后由用户手动提交；不自动重放修改请求。登录框打开和提交前刷新会话，防止久置登录框使用旧 token。注册成功后即切为登录模式，自动登录失败时只需重试登录。

## 6. 检索算法

### 6.1 候选与公开文本

MyBatis 使用固定 SQL 读取有效账号的公开候选，Java 执行显式严格筛选，默认保留 OPEN/HANDOVER 信息。第一版使用内存排序；扩大到生产规模后再改为数据库条件下推、倒排/向量索引召回。拼接 `title category description location` 作为公开文本，严禁拼入 contact、hidden_features、claims.proof。

全半角/大小写归一化，维护校园卡、学生卡、饭卡，耳机、蓝牙耳机等同义表达和地点别名。关键词使用汉字二元片段与字母数字词组的覆盖率，同时提升完整短语命中。类别识别、地点别名、昨天/前天/今天及明确日期只产生用户可见建议。

### 6.2 语义推理

Python 接口 POST /score 接收 `{query, documents:[{id,text}]}`，返回 `{scores:{id:cosine},model,revision}`。限制最多 1000 篇、每篇 2400 字，Java 按批调用，使用 8 秒超时。模型批处理、CLS pooling、L2 归一化后点积；短查询添加模型卡推荐的中文检索指令。文档向量按文本和模型版本缓存，文本修改自然生成新键，不缓存私密字段。使用 torch.inference_mode、eval、local_files_only 和 trust_remote_code=False。

### 6.3 融合

先进行文本相关性检查：归一化的已知品牌别名组、物品名称组和显式型号需在公开文本中得到支持；品牌、颜色或型号明确冲突直接排除。支持苹果/Apple/iPhone/iPad/MacBook/AirPods 等品牌关联表达；型号检查完整字母数字边界，例如 iphone15 不匹配 iphone150。只查询品牌时，品牌别名命中按关键词命中处理。查询中从描述识别的建议类别、地点、日期仍不自动变为严格筛选。

通过上述检查后，需要有词片段命中、纯品牌别名命中，或原始语义余弦至少 0.45，防止零文本关联的弱语义候选混入。0.45 是本轮针对无关键词候选的试验召回阈值，不表示准确率。分数 S=100×Σ(wᵢ×sᵢ)/Σwᵢ，初始权重 semantic=.45、keyword=.25、category=.15、location=.10、time=.05。只加入查询提供且可比较的因素；AI 不可用移除语义项并归一化；原始语义余弦单独保留。综合分低于 MIN_SCORE=30.0 的候选在四舍五入之前排除，避免 29.99 被显示为 30 后误纳入；达标者保留一位小数。分数是检索相关程度，不能用于判断所有权。

缺失颜色不判定为明确冲突；缺少已指定品牌、型号或已知物品名称则不满足相关性检查。地点完整相同得 1，别名相同得 1，同区域部分重合得较低分。时间显式筛选先执行；自动匹配按遗失与拾取方向处理，拾取早于遗失仅降低时间分。无查询按最近更新时间排序且不应用分数门槛；有查询先完成相关性检查与 30 分过滤，再统计 total、按分数/时间/ID 稳定排序并分页，不再展示 nearby“相近信息”。语义服务不可用或无候选但有查询时 mode=keyword，无查询时 mode=recent。

匹配线索只来自确定命中：同类、地点相同、关键词命中、日期接近；语义分只说明“语义相关”。推荐排除本人、同类型和非 OPEN；使用相同融合逻辑。模型故障记录简短错误类别，返回 keyword 模式。

## 7. 页面设计

整体采用暖色校园服务界面：背景 #fbf6ed，面板 #fffdf8，主色 #a44e32，正文 #463329，辅助文字 #79675b，边线 #eadfce。全局正文 16px/1.75，卡片标题 18px，卡片描述 15px，输入控件 16px，辅助文字 12～14px，状态标签 12px；按钮和输入区留出足够点击空间。首页提供搜索框、类型切换、分类/地点/日期/状态筛选、相关度和线索、分页，说明已过滤低相关结果。详情弹窗包含公开字段、图片、申领表单、授权后的联系方式。发布表单明确区分公开描述与管理员可见核验特征。

个人中心分为我的发布、我的申领、消息；根据状态展示编辑、撤回、推荐、关闭、已找回等操作。管理员工作台分为内容审核、申领管理、账号管理、审计记录；操作显示原因输入与明确反馈。手机端单列布局；键盘可操作、字段有 label、状态变化有提示。

响应式断点为 1450px（三列卡片）、1080px（收紧横向布局）、820px（导航换行、隐藏侧栏和装饰）及 560px（卡片单列、搜索按钮独占一行、表单单列）。提供可见焦点和减少动画偏好支持。登录成功提示使用 toast 的 aria-live；过期和登录失败说明同时显示在模态框内，避免普通 toast 被模态框遮挡。

## 8. 安全、运维与验证

密码 PBKDF2-HMAC-SHA256、随机盐、常量时间比较。上传检查真实图像、尺寸和大小，随机文件名，拒绝 SVG/HTML。公开附件只对已公开记录开放；私人证明校验申请人和管理员。SQL 一律参数绑定，排序字段固定白名单；前端使用 textContent 或统一 HTML 转义。

不自动提交源码、创建远程仓库或对公网发布。启动脚本记录 PID 和日志，停止脚本核对进程命令行属于本项目后结束。安装不覆盖系统 Python 依赖，使用项目环境；网络受限时按实际情况记录来源和失败，不冒称模型部署成功。

集成测试使用隔离临时数据库覆盖越权、CSRF、多人申请、并发唯一领取、审核状态、封禁会话、注销限制、私密字段、附件、AI 降级；模型评测单独记录小样本排序和耗时。最终测试报告记录真实执行结果。

## 1.1.2 账号与资料实现

AppConfig 在执行 schema.sql 后读取 PRAGMA table_info(users)，按缺失项添加 phone TEXT NOT NULL DEFAULT ''、default_address TEXT NOT NULL DEFAULT ''、session_version INTEGER NOT NULL DEFAULT 0。迁移可重复运行，不重建用户表。存量账号的字段使用默认值，密码摘要与外键关联保持。

Business.updateProfile 重新读取当前有效用户，以会话身份决定目标，验证昵称、电话和默认地址；改登录账号时校验当前密码、唯一约束，管理员禁止改名。Db 的资料更新同时匹配用户编号、ACTIVE 状态及当前密码摘要，避免并发密码更新后使用旧状态修改资料。审计仅记录动作，不记录资料值或密码。

Business.changePassword 使用 PBKDF2-HMAC-SHA256 随机盐生成摘要，条件更新密码并增加 session_version。登录将当前版本存入会话，Api.user 对照数据库版本；版本不一致拒绝访问。密码修改接口成功后注销当前会话，其他已有会话在下一次请求失效。资料及密码写接口受 CSRF 与尝试频率限制。注销账号清除 phone/default_address 并增加会话版本。

前端通过 #profile 与 #profile-password 显示独立资料页面；主侧栏收起，保留顶部导航。昵称下拉维护 aria-expanded、点击外部/Escape/失焦收起行为。保存资料更新顶部昵称，改账号成功提示下次使用新账号；改密码成功刷新匿名会话并显示重新登录提示。资料值统一转义；默认地址仅用于新发布地点的可编辑初值。

reset_admin.py 是显式本机维护工具，要求 --data 指定已有目录，校验管理员状态后通过 SQLite backup API 创建一致备份并复制旧凭据，随后仅更新管理员密码、撤销其旧会话并记审计。正常启动不调用该工具，安装包不包含个人数据库。
