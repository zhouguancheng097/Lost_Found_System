# AI 辅助设计、部署与开发说明

版本：1.1；更新日期：2026-11-19；初版日期：2026-11-13。本文同时说明网站内的 AI 功能，以及开发过程中 AI 辅助工作的边界与记录方式。

## 1. AI 的作用

网站使用中文句向量模型辅助检索，理解近义词和不同描述方式；Java 系统结合关键词、类别、地点和时间排序。模型不负责账号权限、审核结论、物品归属、交接确认，也不编造匹配线索。

开发助手用于整理需求、编写设计、生成和检查代码、部署本地模型、运行测试。AI 生成内容必须通过代码检查和实际运行验证，不能把计划中的能力写成已经实现的功能。真实执行结果补充到测试与部署记录。

## 2. 候选模型与选择

| 候选 | 适用方向 | 本项目判断 |
|---|---|---|
| BAAI/bge-small-zh-v1.5 | 中文短文本语义检索，512 维，最大 512 tokens | 第一版采用，优先控制内存、冷启动与部署复杂度 |
| BAAI/bge-base-zh-v1.5 | 中文检索，768 维 | 后续用同一标注集比较收益再替换 |
| BAAI/bge-large-zh-v1.5 | 中文检索，1024 维 | 本机可评估，但第一版不增加资源开销 |
| moka-ai/m3e-base | 中文句向量备选 | 后续对照，未在本项目实测前不作效果保证 |

以上 BGE 参数与调用方式来自模型作者的模型卡，不能用公开榜单代替失物领域评测。BGE small zh 的维度为 512，不应误用英文 small 模型的 384 维参数。模型是经过检索训练的编码器，不能直接用未作句向量训练的普通 BERT 替代。

本机已识别约 16GB 内存、RTX 4060 Laptop 8GB 显存；已有 PyTorch 为 CPU 构建，第一版先采用 CPU 推理，不自动替换全局 PyTorch 或安装显卡驱动。

## 4. 推理流程

1. Java 对公开记录做严格条件筛选，构建公开描述。
2. 向本地 POST /score 发送查询和候选，不包含密码、联系方式、隐藏核验特征和申领证明。
3. tokenizer 截断至最大 512 tokens，短查询增加指令“为这个句子生成表示以用于检索相关文章：”，文档不加指令。
4. AutoModel 取最后一层 CLS，L2 归一化，计算余弦相似度；禁用远程自定义代码。
5. 返回语义分，Java 检查品牌别名、物品名称、显式型号和明确特征冲突，过滤无关候选，再融合关键词与结构信息；综合分低于 30 分的结果不进入列表。零关键词命中的候选还需语义余弦至少 0.45。
6. 前端展示候选、可核实线索和模式；故障时降级关键词检索。

缓存仅包含公开文本向量，容量有限；模型版本变更后不复用旧缓存。模型接口仅本机监听，限制文本长度、批量和超时；不提供任意路径加载和代码执行接口。

## 5. 评分与评测

初始融合权重为 .45/.25/.15/.10/.05，查询缺失因素不参与分母。语义余弦和综合分都不是所有权概率。模型卡特别指出应根据业务数据分布选择阈值，因此第一版不声称某个固定余弦分以上就是同一物品。

2026-11-19 第一轮优化按用户要求，将综合相关分 30/100 作为试验展示下限，过滤发生在舍入、总数统计和分页之前。不能将“30%”表述为模型置信度或归属概率；实际采用的是综合相关分 30 分。另设零关键词候选的原始语义召回阈值 0.45，用于排除弱关联文本。品牌、已知物品名称或显式型号缺乏文本支持，以及明确品牌/型号/颜色冲突时，即使语义较高也排除。该规则复用于双向推荐；空查询不应用分数下限，AI 故障仍走关键词规则。两个阈值均为本轮试验参数，需独立标注集进一步验证召回损失，不能把本轮构造样例通过当作泛化准确率。

评测至少包含：同义词、自然语言、品牌型号冲突、颜色冲突、地点别名、日期先后、无关物品、错别字、字段缺失和历史已领取记录。人工指定相关物品，分别执行关键词基线与混合检索，记录 Recall@5、Recall@10、MRR、平均和最大延迟、模型版本。小样本仅用于冒烟和回归，不作为正式泛化结论；正式验收应扩充独立标注集。

不在测试集上反复调参后再宣称独立效果；调参集和最终测试集需分开。若语义检索对明确型号查询造成退化，应调整关键词权重或冲突规则后重新评估。

## 6. AI 辅助开发记录

| 阶段 | 输入与产出 | 核验方式 |
|---|---|---|
| 需求整理 | 用户明确需求、后续认可的优化 → 需求分析 | 角色、状态、权限、验收编号可追溯 |
| 详细设计 | 需求 → 架构、表结构、事务、接口、检索方案 | 检查多人申领与单一领取的一致性 |
| 实现 | 文档 → SSM、前端、Python 服务、脚本 | 编译、隔离数据库集成测试 |
| 模型部署 | 模型卡与本机条件 → 下载、校验、离线加载 | 文件哈希、健康检查、真实向量计算 |
| 验证 | 业务场景、人工标注样例 → 测试报告 | 保存真实结果，不伪造通过记录 |

初始需求与设计已在编写业务代码前形成。若实现因环境或测试证据调整，须同步修订对应文档并标出限制。

第一轮用户反馈包括：登录成功反馈不足、会话失效提示不准确、语义检索只排序而未排除无关项、文字偏小以及页面需改为暖色。已据此同步修改前后端和三份文档，新增会话失效/CSRF 区分、注册后登录、查询过滤/分页边界及前端交互验证。真实模型联调使用独立数据库和测试端口，不修改原有业务记录；结果见《测试与部署记录》及《优化联调结果.json》。模型文件、推理实现和既有小样本原始语义评测未变更；不把原评测数字当作本轮完整检索过滤的指标。

## 7. 运维与限制

首次模型下载需要网络，之后可离线推理。CPU 与 GPU 环境不能混写；使用 GPU 时需另行建立匹配的依赖环境并重新记录延迟。公开图片若含证件号码，应先脱敏；用户不应将秘密细节写入公开描述。备份包含 SQLite 与附件目录，模型可依据 manifest 重下载。

模型已从 Hugging Face 原站下载、完成权重校验并成功离线加载；初版 16 项 Java 集成测试及真实 HTTP 联调通过，本轮扩展为 20 项 Java 测试。首次读取说明时使用镜像，最终权重来源为原站，二者在部署记录中明确区分。详细证据见《测试与部署记录》和同目录的评测 JSON；浏览器可视化验收受当前自动化环境限制尚未完成。

## 离线安装版的 AI 环境（2026-11-20）

用户要求接收者无需另行下载运行环境，因此安装包内置独立 CPython 3.13.3、CPU Torch、Transformers、FastAPI、Uvicorn 及传递依赖，并携带已校验的 BGE 中文模型。开发电脑的 .venv 含绝对路径且复用全局包，不能直接当作可迁移环境。

打包脚本从官方获取嵌入式 Python，隔离用户 site-packages 与 PYTHONPATH，按发行包元数据收集依赖闭包。最终依赖版本记录在安装包 package-manifest.json；模型来源、revision 与文件哈希保存在模型 manifest.json。AI 服务继续设置离线环境变量且只监听本机。

验收使用安装包内的 Python、Java 和模型，在清空常规 PATH、设置无效全局 Python 路径的条件下启动服务，并执行真实 /score 排序与网站 AI 健康检查。该验收证明运行环境隔离和模型可用，不新增检索准确率结论，也不等同于在所有 Windows 电脑上的兼容性认证。
