# 本地手工测试用例

初版日期：2026-11-13；更新日期：2026-11-19。本文供你实际点击网页测试，所有用例初始结果均为“待手工执行”，不是自动通过报告。

## 1. 启动与准备

双击根目录“启动系统.cmd”。服务准备完成后，默认浏览器自动打开网站。系统已经正常运行时，重复双击会直接打开网站，不会再创建一套服务。启动失败时不会提前打开未就绪页面；如果浏览器无法打开，会保留服务并显示可访问地址。

本次已初始化 5 个测试账号、16 条物品、7 条申请。测试账号初始密码统一为 **Demo123456!**。

| 账号 | 用途 | 初始状态 |
|---|---|---|
| demo_finder | 招领发布者，管理自己的信息 | 正常 |
| demo_owner | 失主甲，寻物发布者、申领人 | 正常 |
| demo_claimant | 失主乙，竞争申领、撤回申请 | 正常 |
| demo_banned | 封禁与解锁 | 已封禁，首次登录应失败 |
| demo_delete | 账号注销练习，无进行中业务 | 正常 |
| admin | 管理员审核与账号管理 | 使用 data/admin-credentials.txt 中的原密码 |

实际物品编号与申请编号见 [测试账号与数据](../data/测试账号与数据.md)。测试记录标题都带“【测试】”，不是真实失物。

使用一个浏览器轮流退出、登录即可。若想同时查看双方效果，可用普通窗口和隐私窗口分别登录。手工操作会改变数据，请按下面顺序测试；记录中的“初始状态”不会自动恢复。

## 2. 启动与检索

| 编号 | 操作 | 预期 |
|---|---|---|
| T01 | 服务停止时双击“启动系统.cmd” | 等待就绪后自动打开首页，语义检索显示已连接 |
| T02 | 服务正常时再次双击“启动系统.cmd” | 打开已有网站，不再提示重复启动错误 |
| T03 | 登录 demo_finder，再退出登录 | 显示“登录成功”和对应名称；退出后可浏览但不能发布和申领 |
| T04 | 搜索“学生卡”，信息类型选择招领 | 能找到“【测试】蓝色卡套校园卡”，不要求标题包含“学生卡” |
| T05 | 搜索“装电脑的灰色包”，类型选择招领 | 前几条有“【测试】灰色笔记本电脑包” |
| T06 | 搜索“黑色华为mate60” | 返回对应华为手机，排除白色苹果手机等品牌、型号或颜色明确冲突项 |
| T07 | 分类选择“雨伞”、地点填“图书馆” | 结果都符合所选类别和地点；重置条件后恢复 |
| T08 | 输入“昨天在图书馆丢的黑色雨伞” | 可以看到建议条件；点击“应用建议筛选”后才严格使用建议 |
| T09 | 保持默认“正在进行”，查找“已领取的绿色双肩书包” | 默认不展示该历史记录；切换状态“已领取”后可见 |
| T10 | 日期起始设置晚于结束日期 | 显示日期错误提示，不返回误导结果 |

T06 观察过滤结果，不再只观察排序。综合相关分低于 30 分的记录不展示；分数不代表物品属于你的概率。

## 3. 发布、图片、审核与权限

| 编号 | 操作 | 预期 |
|---|---|---|
| T11 | demo_owner 发布新寻物：蓝色水杯，描述不少于5字，填写地点、日期、联系方式 | 发布成功后处于待审核，在“我的发布”可见，未登录广场不可见 |
| T12 | 同一发布选择 data/demo-files/demo-photo.png 上传 | JPEG/PNG 合法图片可上传，在本人详情可查看 |
| T13 | 上传 data/demo-files/invalid-image.txt | 文件选择器可能先隐藏该文件；通过“所有文件”选入时，服务端仍应拒绝非图片 |
| T14 | admin 在“信息审核”找到 T11 的新记录并通过 | 广场可以查到，发布者收到站内通知 |
| T15 | demo_owner 修改自己的“待审核的银色U盘” | 可以编辑；提交后仍为待审核，其他用户看不到 |
| T16 | admin 驳回该U盘并填写原因，再由 demo_owner 查看 | 发布者能看到驳回原因，可修改后重新提交 |
| T17 | demo_claimant 查看 demo_finder 的物品 | 看不到针对他人记录的本人编辑/删除操作；后台也拒绝越权请求 |
| T18 | demo_finder 修改“已驳回的红色围巾”并提交 | 变为待审核，可由管理员重新审核 |
| T19 | demo_finder 尝试编辑已有两条申请的黑色雨伞 | 提示已有申领历史，不能直接修改关键字段 |
| T20 | demo_owner 在自己的寻物雨伞信息中点击“查看匹配” | 推荐另一类型的招领雨伞，排除自己发布的信息 |

普通浏览器详情不应公开联系方式和隐藏核验特征。管理员查看雨伞详情可见隐藏特征“伞柄内侧刻着 LF-2026”，用于下面的核验。

## 4. 多人申领与交接

建议先完成雨伞场景，再做钥匙场景，两件物品互不影响。

| 编号 | 操作 | 预期 |
|---|---|---|
| T21 | admin 打开“申领管理”，查看黑色雨伞 | 初始有 demo_owner、demo_claimant 两条待审核申请 |
| T22 | 对照雨伞隐藏特征，批准 demo_owner 的申请 | 只有该申请通过，物品变交接中；demo_claimant 的申请仍待审核 |
| T23 | 尝试再批准 demo_claimant 对同一把雨伞的申请 | 拒绝第二位交接人，原批准不受影响 |
| T24 | 分别用 demo_owner、demo_claimant 查看雨伞详情 | 只有审核通过的 demo_owner 能看到联系方式；两人都看不到隐藏核验特征 |
| T25 | admin 点击 demo_owner 雨伞申请的“确认已交接” | 物品已领取，demo_owner 申请完成，demo_claimant 申请取消，双方收到通知 |
| T26 | 回到雨伞详情尝试继续申领 | 不再提供有效申领入口，不会重复领取 |
| T27 | admin 查看“小熊挂件钥匙” | 初始为交接中，demo_owner 已批准，demo_claimant 待审核 |
| T28 | admin 对钥匙的已批准申请“取消交接”，填写原因 | 该申请取消，物品恢复待认领；可再处理其他待审核申请 |
| T29 | demo_claimant 打开“我的申领”，撤回深蓝色保温杯申请 | 申请变已撤回，物品仍待认领 |
| T30 | demo_claimant 对校园卡提交新申请，填写至少10字证明，可附图片 | 产生待审核申请；重复提交进行中申请被拒绝 |
| T31 | demo_finder 尝试申领自己发布的物品 | 没有本人申领入口，服务端也拒绝本人申领 |

你填写的证明可能用于管理员核验，测试时请使用虚构内容。申请人仅能查看自己的证明；发布者不会因发布物品而自动获得申请人的私密证明。

## 5. 账号管理与通知

| 编号 | 操作 | 预期 |
|---|---|---|
| T32 | 使用 demo_banned 和正确初始密码登录 | 提示账号封禁，不能登录 |
| T33 | admin 解锁 demo_banned 并填写原因，再用该账号登录 | 解锁后能登录 |
| T34 | 保持该账号已登录，在另一窗口由管理员再次封禁，再尝试发布或查看个人中心 | 原会话的后续受保护请求被拒绝，不必等重新登录 |
| T35 | admin 再次解锁 demo_banned | 能重新登录和使用 |
| T36 | demo_owner 在仍有未结束发布/申请时尝试注销 | 明确提示先结束业务，不会直接删除账号 |
| T37 | demo_delete 进入“我的发布”，点击“注销我的账号”，输入初始密码 | 无进行中业务，可以注销；之后原账号不能登录 |
| T38 | demo_owner 查看“消息”，点击“全部标为已读” | 只显示本人消息，操作后未读状态更新 |
| T39 | admin 查看“操作记录” | 实际审核、申领处理、账号操作有对应记录；初始化条目标记为 DEMO_SEED_V1 |

## 6. 数据复用与结果记录

本次已为你创建测试数据。根目录“初始化测试数据.cmd”可再次生成丢失的账号清单，但**不会重复创建、覆盖已有账号、重置密码或恢复你已经操作过的业务状态**。测试数据追加前的 SQLite 备份位于 data/backups，具体路径见 data/demo-fixtures.json。不要直接覆盖当前数据库来恢复测试状态，以免覆盖其他业务。

你可以把发现的问题按以下格式发给我：

| 用例编号 | 使用账号 | 操作/物品标题 | 预期 | 实际情况 |
|---|---|---|---|---|
| 例如 T22 | admin | 批准黑色雨伞申请 | 进入交接中 | 待填写 |
