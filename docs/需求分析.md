# 失物招领系统需求分析

版本：1.1；更新日期：2026-11-19；状态：第一轮优化实现基线。初版于 2026-11-13 先于项目代码编写，本次按用户反馈同步修订。

## 1. 建设目标与边界

构建面向校园等小型社区的中文失物招领网站，使用户完成发布、查询、匹配、申领和交接，管理员完成内容审核、申领核验和账号管理。技术约束为 Spring、Spring MVC、MyBatis（SSM），不以 Spring Boot 替代 SSM。

数据库原需求允许 MySQL 或 SQLite。第一版选择 SQLite，原因是本地启动无需安装数据库服务、便于演示和备份；MySQL 迁移作为后续扩展，不声称已经同时支持。中文语义检索在本机运行，不需要付费大模型接口。

系统不提供线上支付、物流、自动身份认证、公开聊天、真实短信或邮件。AI 只辅助找候选物品，不判定物品所有权。

## 2. 角色与权限

| 操作 | 未登录访客 | 普通用户 | 管理员 |
|---|---|---|---|
| 浏览公开信息、查询、筛选 | 允许 | 允许 | 允许 |
| 注册、登录 | 允许 | 已登录可退出 | 已登录可退出 |
| 发布寻物/招领信息、上传图片 | 不允许 | 允许 | 允许 |
| 修改、删除自己的记录 | 不允许 | 受状态约束 | 允许 |
| 修改、关闭、删除他人的记录 | 不允许 | 不允许 | 允许并记录 |
| 查看未公开信息 | 不允许 | 仅自己发布的 | 全部 |
| 提交/撤回申领 | 不允许 | 仅申领他人招领信息 | 同普通用户，不能审核自己的申请 |
| 审核发布、审核申领、确认交接 | 不允许 | 不允许 | 允许 |
| 查看申领证明 | 不允许 | 仅自己的申请 | 全部 |
| 查看联系信息 | 不允许 | 发布者及审核通过的申领人 | 允许 |
| 注销账号 | 不允许 | 自己，须先结束进行中业务 | 普通用户账号，须先结束进行中业务 |
| 封禁、解锁账号 | 不允许 | 不允许 | 普通用户账号 |

管理员账号由初始化过程建立，不开放公开注册管理员。第一版不开放管理员互相封禁或注销，避免系统失去管理入口。

## 3. 功能需求

### FR-01 账号与会话

注册使用唯一用户名、显示名称和密码；用户名为 3～30 位字母、数字或下划线，密码 8～128 字符。密码只存带随机盐的派生摘要。登录后显示角色，退出使会话失效。登录失败有频率限制。封禁或注销后，已有会话也应失去操作权限。

登录成功后明确提示“登录成功”；注册完成并自动登录成功后提示“注册成功，登录成功”。若注册成功但自动登录失败，保留账号并切换为登录模式，避免重复注册。页面停留至会话失效后，点击发布等受保护入口前重新检查身份；失效时显示“登录态过期，请重新登录后再操作”并打开登录框。提交过程中遇到失效也按此处理，重新获取会话验证信息，保留当前已填写表单；登录后由用户再次提交，不自动重复发布。错误密码和有效会话中的 CSRF 验证失败应保留各自的准确提示。

用户注销需再次验证密码；存在自己尚未结束的发布或待审核/待交接申请时拒绝注销，并说明处理方式。注销采用匿名化和逻辑删除，保留必要业务关联。封禁保留原因；解锁恢复使用。封禁账号的公开记录暂停展示，避免继续发起无法完成的申领。

### FR-02 信息发布与管理

信息类型为寻物启事 LOST、招领启事 FOUND。字段包括标题、类别、公开描述、事件地点、事件日期、私密联系信息、隐藏核验特征、图片。标题 2～80 字、描述 5～2000 字、地点 2～100 字；事件日期不得晚于当天。类别使用固定枚举，避免自由输入产生重复分类。

提交后进入待审核；管理员可通过或驳回，驳回必须填写原因。通过后公开。编辑关键字段后重新进入审核。普通用户仅能修改自己的信息；有申领历史后禁止直接修改或删除，以免改变核验依据，可按流程关闭。删除为逻辑删除。管理员对有进行中申领的信息也应先处理申领，避免产生悬空流程。

图片只允许 JPEG、PNG，单张不超过 5MB，最多三张；服务端验证真实格式和分辨率，随机命名。公开图片不能包含未脱敏证件、密码等核验信息。申领证明图片使用独立私有附件路径，受权限控制。实现阶段为保持图片解码校验可靠，第一版不支持 WebP。

### FR-03 物品状态

| 状态 | 中文含义 | 可见性/后续动作 |
|---|---|---|
| PENDING | 待审核 | 仅发布者和管理员可见 |
| REJECTED | 审核驳回 | 可修改重提、删除 |
| OPEN | 寻找中/待认领 | 公开；招领信息可申领 |
| HANDOVER | 交接中 | 公开状态；禁止新申领 |
| CLAIMED | 已领取 | 仅招领信息使用，终态 |
| RESOLVED | 已找回 | 仅寻物信息使用，终态 |
| CLOSED | 已关闭 | 不再接受申领，保留历史 |

已领取与已找回不能再次提交申领。申领人数与物品最终领取状态分开存储。

### FR-04 多人申领与核验

只能对他人处于 OPEN 状态的招领信息提出申请。每人每件物品最多一条进行中申请；填写遗失时间、地点、未公开特征等证明，支持可选证明图片。申请状态为 PENDING 待审核、APPROVED 审核通过、REJECTED 驳回、WITHDRAWN 撤回、COMPLETED 完成、CANCELLED 业务取消。

完整流程：多人申请 → 管理员核验证明 → 只批准一人 → 物品进入交接中 → 线下交接 → 管理员确认完成 → 物品已领取，其他待审核申请结束并通知。

批准不等于已领取。交接失败时管理员可撤销批准，物品恢复 OPEN；不得批准已封禁/注销的申请人。用户可撤回尚未批准的申请；已批准申请需管理员处理。审核不得由申请人本人完成。并发批准两个申请时最多一个成功，必须由数据库事务和条件更新保证。

### FR-05 混合检索（重点）

1. 输入支持短关键词和自然语言，最大 200 字。
2. 用户主动选择的类别、信息类型、地点、事件日期区间、状态为严格筛选。默认仅浏览 OPEN、HANDOVER；可以选择历史终态；待审核信息不进入公开检索。
3. 系统从文字识别出的类别、地点、相对日期仅显示建议，不自动作为排除条件。用户确认后应用。
4. 关键词检索比较物品名称、品牌型号、颜色、特征；进行全半角、大小写、空白和常见同义词归一化。
5. BERT 类句向量模型计算中文语义相关度，处理“校园卡/学生卡”等不同说法。
6. 综合权重初始为语义 45%、关键词 25%、类别 15%、地点 10%、时间 5%。查询未提供的因素不参与，剩余权重重新归一化；物品字段缺失不判定为明确冲突。
7. 先检查文本相关性再排序：查询明确包含的已知品牌、型号和物品名称必须得到对应公开文本支持，不能仅凭同色、同地点返回无关物品；明确的品牌、型号或颜色冲突直接排除。品牌别名应支持“苹果 / Apple / iPhone”等表达。没有明确冲突的缺失颜色不单独作冲突判断；缺少查询指定品牌、型号或已知物品名称的文本不满足本轮相关性要求。分数不能解释为归属概率。
8. 时间比较使用遗失/拾取事件日期。自动匹配优先拾取日期不早于遗失日期；冲突降低排名，用户的严格筛选除外。
9. 采用综合相关分 30 分（满分 100）作为本轮试验下限，低于 30 分的结果过滤，不再通过“相近信息”保留无关物品。无关键词命中时，只在没有上述特征冲突且语义余弦达到试验阈值 0.45、综合分也达标时保留同义表达。过滤在总数统计和分页之前完成；默认每页 10 条。无结果显示放宽条件提示；空查询仍按原规则浏览全部符合显式条件的信息，不使用分数过滤。阈值需后续用独立样本继续评估。
10. 展示可核实的匹配线索、相关分和检索模式。模型故障自动降级到关键词和条件查询，并明确提示。
11. 标题、类别、公开描述、地点进入模型；私密联系方式、隐藏特征、申请证明不得进入公开索引或模型日志。

### FR-06 双向推荐

用户查看自己已审核通过的信息时，可查看另一类型的 OPEN 信息推荐；寻物匹配招领，招领匹配寻物，排除本人记录、封禁发布者、删除记录和已领取记录。复用混合排序规则，最多展示 10 条。发布尚未审核时提示审核通过后查看推荐。

### FR-07 个人中心、通知与管理台

个人中心包含我的发布、我的申领、站内通知、账号注销。审核、批准、驳回、交接完成、取消和账号处理产生站内通知；用户仅可读取自己的通知并标记已读。

管理台包含全部信息列表、内容审核、全部申领、用户列表、账号处理和操作记录。管理原因、操作人、目标、动作和时间写入审计记录；日志不记录密码和完整证明。

## 4. 非功能需求

- 所有权限在服务端检查，不信任页面按钮和请求中的用户 ID、角色、状态。
- 使用参数绑定查询，前端渲染转义；会话 cookie 为 HttpOnly、SameSite=Lax；更改数据的请求验证 CSRF token。
- 本地默认只监听 127.0.0.1；上线需 HTTPS、反向代理、独立账号及备份。
- 使用数据库外键、唯一约束、条件更新和事务防止重复申领与重复交接；SQLite 设置外键、WAL 与忙等待。
- 中文界面，采用奶油米色背景、陶土橙棕主色和深棕文字；正文基准 16px，表单输入 16px，辅助信息以 12～14px 分层，提升可读性。保留响应式布局，窄屏物品单列、表单单列，搜索按钮避免挤占输入框；表单有明确错误提示、成功反馈、空状态和加载状态。
- AI 服务请求限制批量和长度、设置超时、缓存公开描述向量；AI 不可用不影响申领和账号功能。
- 演示规模目标 1000 条记录；热检索目标 3 秒以内，冷启动单独测量。以上是验收目标，不视为已测数据。
- 数据库、图片、私有附件和模型位于项目内部可识别目录，支持停止服务后备份。

## 5. 验收与可追溯性

| 编号 | 验收场景 | 预期 |
|---|---|---|
| AC-01 | 两用户修改同一记录 | 仅发布者成功，越权请求被拒绝 |
| AC-02 | 两人同时申领同一物品 | 两条待审核申请均保留 |
| AC-03 | 同时批准两条申请 | 仅一条通过，物品交接中 |
| AC-04 | 完成交接 | 一位领取人，其他申请取消，通知产生 |
| AC-05 | 编辑待认领但已有申请的记录 | 拒绝修改关键字段 |
| AC-06 | 封禁已登录用户 | 该用户原会话后续请求被拒绝 |
| AC-07 | 查询校园卡/学生卡、同义地点 | 目标能进入候选前列，展示真实线索 |
| AC-08 | 查询字段缺失或明确冲突 | 缺失不作冲突，明确冲突降分 |
| AC-09 | 关闭 AI 服务后查询 | 关键词和筛选仍可用，有降级提示 |
| AC-10 | 未授权访问证明或联系方式 | 不泄露；审核通过者才可见联系方式 |
| AC-11 | 有进行中业务时注销 | 拒绝，提示先结束业务 |
| AC-12 | 缺少 CSRF 或上传伪装文件 | 拒绝 |
| AC-13 | 登录或注册后自动登录成功 | 分别显示“登录成功”“注册成功，登录成功” |
| AC-14 | 页面停留至登录态失效后点击发布或提交 | 明确提示登录态过期，打开登录框，保留已填表单，重新登录后可再提交 |
| AC-15 | 查询“苹果”且存在手机、雨伞、其他品牌物品 | 仅返回匹配苹果品牌的物品；支持 Apple/iPhone 别名 |
| AC-16 | 查询低于 30 分、明确冲突和不存在的物品 | 排除结果后再计数分页；无结果显示空状态；空查询仍可浏览 |
| AC-17 | 桌面和窄屏查看首页、表单和列表 | 暖色风格、清晰字号、内容可读，窄屏无布局挤压；视觉实测结果单独记录 |

检索评测采用人工标注的独立查询集，记录 Recall@5、Recall@10、MRR、延迟和失败案例；演示小样本不代表真实准确率。开发结束应补充实际测试结果与未完成项。

## Windows 安装交付补充（2026-11-20）

根据用户要求，增加 Windows x64 离线安装版。安装包应内置网站、Java、独立 Python 环境、CPU AI 依赖与中文模型；接收者安装后可通过桌面快捷方式启动并自动打开浏览器，无需单独下载运行环境。支持 Windows 10 1809 及以上 x64 系统。

交付包不得包含开发电脑的业务数据库、账号凭据、消息、公开图片或私有证明附件。首次启动创建空业务库和随机初始管理员密码；通过开始菜单查看管理员账号。开始菜单提供停止服务、数据目录和卸载入口。升级与卸载保留用户数据。网站仍仅监听本机，不自动成为多人共享的在线服务。源码通过仓库分发，编译好的安装包通过 Releases 分发。

## 安装版启动与测试数据补充（2026-11-21）

启动脚本确认网站与 AI 就绪后，启动进度窗口应自动关闭，再打开浏览器；窗口退出不停止网站和 AI。安装版保留独立数据库，但提供用户主动触发的“初始化测试数据”入口，追加虚构测试场景并自动备份；不得复制开发数据库或重置管理员密码、已有账号与业务。初始化可重复执行，保留已修改状态；测试清单写入安装版自身数据目录。
